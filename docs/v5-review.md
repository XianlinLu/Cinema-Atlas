# v5 自动执行流程审查与调整

## 本次约束变化

用户确认 Lumina 当前单文件上限为 30,000 字符。本版按 29,600 个 UTF-16 单元保守打包；旧版 20,000 字符兼容包仍留在 dist 历史文件中。

## 调整点

| 旧版需要澄清或改进的地方 | 本版处理 |
|---|---|
| 46 个文件接近数量上限；主文件约 19,676 字符承载了阶段入口和多个专项细节 | 59 种风格全文重新分片，35 个文件、含目录共 38 项；主入口降至约 9,362 字符，专项内容按阶段读取 |
| “确认后继续”缺少统一的下一动作选择和恢复检查入口 | 新增 runtime-control：对账、选择就绪动作、真实调用、观察、保存、循环；明确哪些情况允许等待／结束 |
| 后续续写依赖前段，但逐段用户确认安排在全部生成之后，两个批准层级容易混用 | 总表授权的连续镜头可消费 QC_READY 前段；后期仍要求每段当前版本 USER_APPROVED |
| 配乐卡点或素材头尾裁切改变最终时间轴，容易误改原生产表并导致不必要的重做 | 原生产表与后期编辑映射分别保存；重算字幕／音轨位置和最终时长，按修改影响范围失效 |
| 模型随机背景音乐、后期统一配乐以及对白字幕、风格必要文字可能混用 | 明确音频与文字角色；去模型 BGM 后再确认，后期单独添加已规划配乐；字幕选择不误删故事标题／数据标签 |
| 任务提交、生成、技术检查、用户批准和可下载交付容易被笼统写成“完成” | 分别记录实际状态与证据，导出前核对当前版本批准，只有真实可下载产物才进入交付完成 |

所有既有创意节点、59 种完整风格、Seedance 2.5／16:9 默认、去配乐、同场景续写、硬切、声音绑定、原生后期与确认修改循环均保留。完整需求见 [requirements.md](requirements.md)。

## 验证范围

本次检查打包数量与长度、全部风格重建哈希、重新打包前后正文一致性、引用路径、Skill 元数据及发布内容。未运行新增单元测试，也未在 Lumina 执行实际付费媒体生成、后台续跑或 Video Editor 全流程。新增调度规则属于 Agent 执行约束，不是独立安装的工作流引擎；实际自动化仍依赖宿主暴露的原生能力。
