# Durable production, native reviews and Video Editor

## Priority and actual capabilities

The latest user sequence governs: idea → script approval → 16:9 character approval → role voice choices → playable 20–30s audition approval → full shot-table approval → generate all shots → user approval of EVERY shot version → post-production choice → native Video Editor → final review/revision → final export and download. Earlier unconditional assembly instructions do not bypass these gates. Preserve selected catalog style grammar, exact approved speech and existing audio/parameter safeguards in SKILL.md and production-requests.md.

Discover real native canvas schemas: Question, images, speech/voices, video, task status/continuation, and Video Editor project/media/timeline/caption/preview/export/download operations. The screenshot establishes UI labels, not callable names or parameters. Save the actual bindings and supported ports. Use only the host's native nodes and supported connections; a fake node, printed JSON, editor description, HTML project, external editor or ffmpeg result is not a native Video Editor operation. Do not install/run OpenFilm or redirect this workflow to its Studio. If a required tool is missing, report its precise limitation through native recovery and retain state; a Skill cannot register tools. If Question itself is missing, state the blocker before new paid work rather than imitate a card.

If background resumption is absent, state that capability limit once, with preserved state. Read back long note writes; repair failed writes without shortening approved scripts.

Invalidate only changed artifacts and genuine dependents. Re-read the latest editor state before edits so concurrent human changes, locked tracks and existing styling survive. ## Native cards: all decisions stay inside Question

Show real images/audio/video/table before review. Use the runtime tool, concise labels and real previews/IDs. `agents/openai.yaml` is metadata and cannot create a tool. A native canvas worker unable to ask must return artifact/version and proposed question to a parent with Question, then await its actual response. Do not print choices or request a reply in the main chat.

- **剧本确认:** 通过并继续 / 调整剧本 / 更换风格. Infer concept/style and write the script BEFORE this card. A style revision browses the full indexed catalog in manageable native batches. Do not force 59 items into one card.
- **角色三视图确认:** 全部通过 / 调整指定角色 / 重新查看. All relevant images must be visible; approve no unseen assets.
- **角色试音要求:** 2–3 complete timbre/pitch/language/accent/pace/performance profiles per speaking role, with one recommendation. Group questions only within actual schema limits. Honor already supplied requirements.
- **角色试音确认:** 全部通过 / 调整指定声音 / 再听一次. Every required actual sample must play. Mute roles need none; narrator has its own voice without a fake image.
- **镜头生产总表确认:** 通过并生成全部分镜 / 调整指定镜头 / 重新查看表格与对白. This authorizes automatic generation and technical repairs, not unseen shot approval or post-production selection.
- **分镜成片确认 · {shot_id}:** 通过此分镜 / 修改此分镜 / 再看一次. Include real clip, role/line context, version and duration. Iterate every planned shot; a batch may contain one question per actual shot but never approve remaining shots from a single response. Offer targeted modifications; if free instructions are needed, collect them inside native Other/text input. Repair and reapprove only affected shots, then resume outstanding reviews.
- **后期制作方式:** 仅剪辑拼接 / 仅添加字幕 / 剪辑拼接＋字幕（推荐） / Other. Use built-in Other instead of duplicating it when available. Display the actual scope/consequences; never assume the recommendation was submitted. “Both” immediately enters native Video Editor with both operations enabled. Stitch-only adds no new captions; subtitle-only preserves an existing approved timeline or captions each separate approved clip without silently concatenating. Other captures desired custom scope (including no post-production) through the native input; resolve only genuine ambiguity using native choices. Explicitly declining editing delivers labeled approved clips, not a claimed stitched film.
- **剪辑成片确认 · {revision}:** 确认，导出下载 / 继续修改 / 重新预览. Show the exact editor draft/preview, scope, music/subtitle status and revision before asking. A positive response authorizes exporting that revision; it is not permission to publish anywhere.
- **剪辑修改说明:** after “继续修改”, require nonempty native-card text: which shot/timecode/track, what is wrong, and how to change it. Use actual free-text schema or built-in Other; do not demand main-chat typing. Do not treat the “modify” click alone as a complete edit request. If text is ambiguous, use a focused follow-up native card; if no native text entry exists, report a host blocker. Apply the user's requested change in the SAME native editor project, inspect, produce a new preview/version and ask 剪辑成片确认 again. Repeat until actually approved or explicitly paused. Reopen script/voice/shot review if the edit materially changes those approved assets.
- **异常处理:** offer actual supported repair/creative alternatives, provider review or save/pause only for a real blocker. No moderation bypass option, dummy success or hidden omission. Batch unresolved independent failures into one appropriate recovery interaction where possible.

## Native Video Editor: adapted editing method

Method reference: OpenFilm's SKILL.md and packages/openfilm/MANUAL.md, revision cf6cd6fa9b3d4ee50dd963853ee6ca4f8354ecf4. Apply its editable tracks, source-range trims, preserving human overrides, timed subtitles, preview inspection and export discipline through Lumina's actual native editor. OpenFilm's HTML syntax, CLI and page-rendering contract are not Lumina tools; do not claim interoperability. Runtime reference access is unnecessary for routine editing because the relevant method is adapted here.

1. **Open and resolve assets.** Invoke actual native Video Editor creation/open with the intended canvas/project context. Reuse its saved draft across revisions. Import approved canvas video/audio assets through the native Canvas/media path or actual tool asset ports; opening an empty editor is not import success. Confirm each required file is accessible and fully ready. Record the returned media and project identifiers. Do not replace source clips with placeholders or import the whole unrelated canvas.
2. **Read, save and assemble.** Read the latest draft immediately before changes and save a supported revision/snapshot. Keep source media, user-locked tracks, overrides and unrelated edits. Use native clip instances referencing original media with explicit source in/out, timeline start, playback rate, transforms/crop and gain. Trim/reorder non-destructively rather than re-encoding intermediate files. Keep visuals, title/captions and audio on separately editable supported tracks; use the editor's actual compositing rules with titles above the picture. Avoid silent duplicate clips, black gaps and unintended overlaps. Preserve approved scene order unless the user requests a change.
3. **Music-driven cuts.** If planned music exists, use the actual selected ready audio. Listen/inspect its waveform and obtain genuine beat, downbeat, phrase, drop and ending markers using supported native analysis or observed playback; do not invent BPM/markers. Place key transitions, reveals and action accents on suitable musical beats/phrases. Choose the nearest narratively valid cut, not every beat. Use source handles and shot placement first; preserve exact dialogue, emotional holds, complete actions and lip-sync. Never accelerate speech, remove words or change identity to hit a beat. When music and approved content cannot fit, use a native choice for a specific substantive timing/music revision. If no analysis/playback capability is available, state what cannot be verified instead of claiming checked beat alignment. Absence of music is not permission to generate one without scope/rights support.
4. **Dialogue and sound mix.** Place approved role speech and narrator on correct tracks; keep original sync and separate off-screen speech from visible mouths. Mute unwanted successful-source native speech only as part of the approved sound plan. Adjust planned music with fades/ducking and avoid double audio, clipping and abrupt endings. Move linked dialogue/foley with clips during ripple edits. Real lip-sync correction remains required where the spoken picture changes; adding an audio track alone proves no mouth match. Follow SKILL.md's policy rules for blocked outputs.
5. **Subtitles only when selected.** Derive captions from actual final approved speech/transcription with verified timestamps, punctuation, speaker/language and line breaks. Use native captions/text tracks or supported SRT/VTT import; never assume a specific port or format exists. Keep timed text editable and avoid duplicate burnt-in/native captions. Follow safe areas, readable contrast/size and normally one or two lines; preserve exact approved text and do not translate unless requested. If source-aligned timing exists, map to the edit using timeline_start + (source_time − source_in) / playback_rate, respecting actual transitions/linked timing. Recalculate after trims, speed, ripple or reordering, and inspect cues at boundaries. Retain transcript/source timing when only clip speed changes; do not regenerate speech to stretch it. No captions must remain on music-only spans unless approved as titles/lyrics.
6. **Preview and inspect.** Save the actual draft and show its real native playable preview, or a supported review export if a playable preview requires one. Check the whole sequence/contact-sheet equivalent plus critical transitions, first/middle/last frames, audio and caption boundaries. Confirm shot/line coverage, order, trims, ratio, real duration, stable voice/character, music accents, complete dialogue, lip-sync, readable captions and no missing assets, gaps, duplicate spans, unintended muted/hidden tracks or extra sound. A contact sheet cannot prove audio sync; use actual playback/analysis. Distinguish checks performed from unavailable ones. Return this exact revision to the final native review card; do not claim editing is complete from a tool acknowledgment.
7. **Revise in place.** Read current draft, apply only the native-card change request, preserve unrelated human edits, retime dependent captions/audio/beat markers, save a new revision, recheck affected areas and overall continuity, then return to final review. No whole-project restart or regeneration unless the requested change genuinely requires it.
8. **Export after approval.** Export the exact user-approved current revision through native Video Editor. Use project ratio/timebase and supported output settings; prefer a broadly playable MP4 when available without inventing codec controls. Await the real export task, verify completed artifact ID, accessibility/download and actual duration/picture/audio/captions. If draft revision changed, return to review rather than exporting an unapproved revision. If export changes the appearance, re-review that changed result. Exporting, exporting subtitles separately and downloading are different operations; return the real downloadable media file/URL plus native editable draft and optional subtitle files when actually available. An editor URL, cloud draft or invented MP4 link is not the requested download. An expired link is refreshed through actual host support.

## Completion and local recovery

Normal film completion requires all current shots approved, submitted post-choice, actual native editor project for selected editing, returned final approval for its current revision, successful downloadable export with approved shot/line coverage and audio/subtitles matching scope. Every required shot's approved content is represented once unless intentional reuse was requested; multiple non-overlapping instances of one source are not duplicate content by themselves. No pending required job or unresolved blocker is marked done. User explicitly declining post-production gets clearly labeled approved source clips, and only the matching clip-delivery mode is complete.

Technical repairs preserving content continue automatically with bounded retries; policy/creative changes use native choices. Keep correct clips, voices and edits. A failure of one role/shot/export does not erase independent successes. No failure is hidden by dropping that shot or delivering a silent/incomplete movie. Deliver the approved downloadable result and any actual draft, script, table, source/credit information and subtitle assets, identifying genuine limitations without claiming unsupported tools ran.
