# Native audio input preparation and empty-content recovery

## Scope and observed evidence

Read this before EVERY audition, exact shot-speech, music or sound-effect audio submission and when its native input resolution fails. The user's repeated BALLMAudio response contains `GenInputsFromPipeline ... validate audit content 0: content id is empty` and code 15000. This is evidence of an empty content identifier during input/audit validation, not proof that spoken text is empty, a character picture is missing, concurrency is excessive, copyright was rejected or a particular model is unavailable. The message does not reveal the missing input type. Numeric 15000 alone is not a universal error definition. Nested request/log IDs and different timestamps should be recorded without assuming they prove stale assets, a prior user's task, or the same underlying failure.

Use actual exposed schemas, node inputs, producer status, registration results and error details. Do not invent an internal audit inspection or content-registration API. Skill text can reduce invalid submissions and repair accessible inputs; it cannot intercept Lumina's own modal UI or guarantee a working internal content service. Closing a popup is not a repair.

## Prepare a minimal operation-specific input set

First determine the REAL audio operation and its required inputs. An audio wrapper name does not specify whether it performs speech synthesis, original voice design, voice-reference/clone processing, music or effects. Preserve approved voice choices and language/performance; never choose a reference-dependent route merely because the canvas contains character images.

| Real supported operation | Resolve according to its actual schema |
|---|---|
| Existing-voice speech | Exact nonblank spoken text plus a compatible real voice/settings handle; no picture/audio reference unless this operation requires or intentionally uses it |
| Original voice design / text-described speech | Actual supported descriptive profile/settings and nonblank test/script text; no requirement for the audition's own FUTURE voice/audio output |
| Reference-conditioned speech or explicitly authorized cloning | A genuinely required existing ready reference/voice of the correct type and ownership; never create an empty reference to enter this mode |
| Music or effects | Original production brief and actual required controls/assets for that route; do not inherit role-picture or future voice inputs accidentally |

The table is conceptual, not a provider argument list. If the desired operation is absent, preserve the request and use the existing native capability-recovery gate; do not substitute another voice/engine, clone mode or content scope silently. Ordinary logical character→audition association belongs in project metadata/labels or a genuine non-input relation. A graph connection to an execution input may be compiled into content even if it was intended only as a label: inspect actual port semantics where exposed. Keep user-required conditioning and valid inputs intact.

Create one immutable input/job record per role/line/cue and version. Store source script/profile, exact text/brief, operation, required inputs, allowed intentional optional inputs, saved node configuration and request fingerprint. Do not share or append to one mutable batch reference list. Do not attach the whole canvas or copy an old node with unresolved inherited reference ports. Reuse a valid existing node, but inspect its actual saved inputs rather than assuming a visible caption reflects its payload.

## INPUTS_READY barrier before execute

Do non-generating preparation first. A ready-looking node, successful save call or placeholder is not evidence of a ready content reference.

1. **Text/profile:** resolve actual script text or audition copy, trim only accidental boundary whitespace and require meaningful nonblank content. A file name, variable token, “see script above” or placeholder is not spoken text. Preserve exact approved lines, owner/language and requested performance. If the actual route accepts inline text, use that documented path. If it requires registered text content instead, materialize/register it through the REAL supported operation and retain its returned ready handle. Do not invent registration fields or require registration when inline text is sufficient.
2. **Each required reference:** obtain its real upstream output and the correct route-compatible identifier through supported resolution. Check producer task success, accessible nonempty media/text, project/session access, intended owner/version and any exposed upload/registration/readiness state. A task ID, canvas node ID, voice ID, URL, media asset ID and internal content ID are NOT interchangeable. Nonblank syntax alone is not validation; a URL is not a registered content ID merely because it opens in a browser.
3. **Optional inputs:** omit unintended empty/whitespace/null/unresolved reference items using the actual schema. If an empty collection is required and valid, use its declared form; do not fabricate nonempty dummy items. Remove only a diagnosed erroneous optional execution binding through actual native controls, preserving the source image and logical role link. Do not disconnect valid required input or replace it with a placeholder to force submission.
4. **Save and resolve:** save the actual node's intended operation/text/settings/bindings through supported controls and read back current inputs where available. Reconcile pending registration or shared-canvas changes under runtime-control.md before dispatch. A required reference that is uploading/processing is not ready; query its existing producer/registration with actual host continuation, not repeated audio-generation calls. A terminal empty input is a repair/blocker, not an endless pending wait.
5. **Final input check:** compare the concrete input set with the immutable role/line record and confirm no missing required input, no stale cross-role reference, no future-self/circular dependency and no unresolved optional execution item. Use a genuine native non-generating validator/preview if offered. Never execute an audio-generation job as a probe for readiness. If the wrapper hides compiled inputs, validate all observable supplied fields and record that internal resolution is unverified; do not claim access to hidden internals or invent a validator. Unresolved required external inputs cannot pass this barrier.

Mark INPUTS_READY only for the current saved input version and actual supported route. Changed input/profile/reference versions invalidate that readiness. A local fingerprint helps locate prior dispatch; it is not provider idempotency. Resolve every previous attempt's acceptance through runtime-control.md before any retry, even if the current error occurs during input validation.

## Submit the actual deliverables automatically

Generate the first REAL requested audition end to end; no extra paid diagnostic sample. Default the remaining ready-role jobs to a serial automatic queue, with no user “continue” between roles. Keep distinct operation-specific bindings for audition master, exact film lines, music and effects. Any concurrency must respect actual supported quotas and healthy resolved inputs; serial ordering alone does not fix an empty ID.

On success, resolve and play the actual output; verify text/owner, voice, measured duration and clean sound before GENERATED. Submit/accepted/Completed/tool-toast states do not establish output success. Audition masters still target 20–30 seconds; exact shot speech keeps its real wording/duration, and music/effects follow their own plan. An image can remain a logical reference without being an audio request input.

## Automatic repair after an empty-content error

1. Save exact outer and nested error/request/log IDs, operation, node, role/line, input version, dependency map and current acceptance evidence. Query a known accepted task; unknown acceptance forbids duplicate paid submission. Repeated notifications of the same task/log are one failure, not additional attempts.
2. Inspect the actual failed node and submitted/saved inputs where exposed. The phrase `content 0` identifies an indexed validation item, not necessarily the first image, voice or text in the user's mental list. Resolve its type/producer from actual tool evidence; do not guess it from a screenshot.
3. Apply ONE evidence-backed native repair: resolve a completed producer's correct output; finish exposed pending upload/registration; rebind a stale required handle from a verified ready source; supply the actual missing text through the supported inline/registered route; or omit a diagnosed empty optional item/incorrect execution edge. If the operation was accidentally reference-dependent and a supported no-reference route genuinely matches the requested original design before approval, correct that configuration without changing the requested profile. Preserve approved voice identity; any material voice/engine/content change requires the relevant native decision.
4. Read back/revalidate all observable required inputs and record the before/after difference. Retry the SAME logical audio job only AFTER an observed repair and resolved acceptance, at most once for that repair, within the existing total maximum TWO distinct technical-correction retries. Do not call the unchanged payload again, reset its budget by creating another node, or cycle through models/routes hoping the error disappears. A scheduled wait alone or a new node name is not an input repair.
5. If the binding cannot be edited and evidence shows the node itself is unusable, a supported replacement of ONLY that audio node may be necessary after task acceptance is resolved. Rebuild its verified minimal inputs; keep original role images and correct audio. Replacement consumes the same logical job/repair budget, and must not clone the broken input graph. It is not a routine first response.
6. If observable inputs are valid but the wrapper still reports an empty internal ID, do not fabricate a cause or continue blind retries. Save an internal-resolution blocker and stop that faulty route's new submissions. Prepare independent assets without using that failing path, preserve successes, and use one genuine native recovery card only at the actual dependency barrier. Missing internal registration/status capability may require platform investigation. Do not promise automatic repair of an inaccessible backend.

## Prevent a batch of repeated popups

When one shared audio route/input-template fails with unresolved empty content, hold NOT-YET-SUBMITTED jobs using that same unresolved path. Do not execute each remaining character to discover the same error, or run the whole canvas including known-invalid nodes. Already accepted jobs are still reconciled; genuinely independent ready routes can proceed if the shared canvas is healthy. Release the held queue only after an observed shared-input repair and the first repaired real deliverable succeeds, or after each item is proven unaffected by the diagnosed fault. Never classify jobs as independent merely because their role names differ.

Expose normal progress without asking for routine technical approval. After automatic technical repair, resume the current real audition/line and remaining queue; keep existing creative approvals and all later native review gates. A persistent blocker gets the existing native recovery interface with only actual supported actions, preserving a readable support summary; do not contact support automatically. If the host supplies non-modal status/error handling, use its actual supported capability; never invent `silent`/`suppress_errors` flags or hide a failed stage. Lumina may still display the first backend error before the agent receives it. Reducing bad calls and preventing repeated batch failures is the achievable Skill change, not a guarantee that all platform popups disappear.

This recovery does not alter policy-rejection handling or permit extracting blocked results. It also does not authorize silent film shots: all intended speech/effects must be audible under audio-postproduction.md before shot confirmation, regardless of how audio inputs were prepared.
